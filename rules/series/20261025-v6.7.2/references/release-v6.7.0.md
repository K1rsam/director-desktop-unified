# v6.7.0：岗位供料与单集执行

版本 `20261024-v6.7.0-execution-packets`，基于v6.6.0。本版把机械操作移到本地工具，让分集作者集中完成统筹与主创，整编者集中读完整稿并改具体问题。

- **岗位包**：从经过审核的依赖路径自动算hash，完整源、必要设计、当前状态及实际入口只按内容保存一份，同时保留全部来源。author/finisher/reviewer各有有效规则视图；灵墨v7内部小数时间一次适配，源规则原文件与指纹留存。不会自动猜相关素材或用摘要替代完整材料。
- **正常交接**：作者齐稿后handoff给真实新上下文，不再转pending、resume、claim或另写恢复报告。候选、已有交接说明和前集实际绑定保持可核；旧作者不能继续完成本集。
- **同版采用**：一条episode_execution命令顺序完成sync/check/export/verify，核岗位包source/plan/selection与成稿一致，绑定源锁、相关资产、规则、工具、预览与目录。handoff的新流程必须提交该收据才可complete。
- **断点复用**：同输入复用成功步骤；半导出保留旧文件并另建完整双文件。相关输入变化产生新候选，未用资产新增和单纯Skill维护升级不重跑已采用集。状态检查在同次调用共用验证与总库读取，避免每个边界反复启动进程。失败不会重新购买创作，也不自动改正文。
- **实际路由**：主控使用新命令，执行者只接当前岗位，不重复总入口流程。已授权幻想补漏同次交回计划、选择和完整候选，再由主控核定同版包。完整主创、四项常驻方法、幻想许可、整集整编、局部精修和非作者复核均保留。

首季范围、台词独立冻结、后期说明隔离、完整资产设计、灵墨v7与白图合同延续。旧context_packet和无handoff旧工程可继续使用；不修改桌面Skill、3008服务或在制作品。模型与强度仍遵从本工程已有明确选择，没有静默升级或替换。

使用方法见[岗位包](job-packet.md)与[单集执行](episode-execution.md)。本版发布的是执行能力改进；测试与分发记录见[验证记录](validation-report.md)。未据此宣称创作质量已追平3008、节省固定Token/费用、Mac已实测或新剧本能零干预跑完；这些需要后续同源对照及完整生产验收。
