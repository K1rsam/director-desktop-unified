# 完整资产交接与后续生图接口

选季项目先按[季范围合同](season-scope-contract.md)绑定productionScope/hash，完整总库不等于本次生图清单。用assets image-queue从选季内明确用途生成series-image-queue-v1（精确ID/设计版本/文件名/用途），交生图Skill模块22；其批次validator通过前不派图。后续资产不提前设计/出图，已有图片的保留也不算新图授权。季终另存[续季对接](season-continuation.md)，区分计划/实际尾态与候选图/用户采用。

本合同在阶段2安排资料、阶段4打包时读取。分镜与资产设计由本Skill完成；后续独立生图技能接续本次采用结果。当前不创建生图技能、不调用图片服务，不因准备交接提前假定真实图片已存在。

源有剧情系统时，交接资料须含逐系统的有效[呈现决定](system-presentation.md)、生效范围、所据源与相关设计版本；无独立视觉资产如实标注。不能只交化身图片名而丢掉原声、可见/可听/接触及切换边界。

## 两种范围保留在同一次交付

**灵墨导入包**沿用[v7合同](lingmo-v7-contract.md)：完整MD、同版图片引用目录、纯PNG白图文件夹/ZIP。三行和白图只对应实际 `imageBindings` 的并集，不代表全剧总库。图片目录保持只有图片；制作资料另放同级文件夹。

**资产接续资料**另存一个版本化目录，至少包含：

1. 全剧初始资产基线及最终当前总库，保留稳定ID、原名/别名、语义类型、家族/父子状态、源事实与坐标、适用集场、完整设计、短卡、采用状态及补项记录。保存总库的 `current.json` 与其实际引用的不可变快照；初始及被材料引用的历史快照同时带走，完整历史仍在工作区保留。
2. 从该最终快照生成的可读资产总表，列全库所有项及状态，区分已用图片、纯声源、仅提及、未使用和待设计项；不能只导出MD三行或白图清单。总表是只读投影，改动须回到同一总库，不能成为另一份手工维护的命名权威。
3. 项目视觉方向、关键制作决定、导航/状态和设计适用范围，以及设计所引的可读源材料。附带源文本/源索引供回查，必要的版本化设计附件一并复制；相对路径都能在交接目录解析，不依赖原电脑绝对路径。
4. 最终采用分镜的结构化bundle、同版灵墨MD与 `lingmo-v7-assets-v1` 图片目录、最终消费回执及必要状态说明。使用关系区分集/场/单元、现实/媒体/主观表现和纯声音，不通过重新扫MD猜身份。

交接清单写明源版本、方向版本、总库ID/版本、各文件实际相对路径及未完成范围。历史快照或回执含旧绝对路径时保留原件字节，另在清单记录旧路径到包内相对路径的映射；不能改旧快照再沿用旧hash，也不能要求下一台电脑仍有原目录。初始基线、后续回补、最终当前总库都保留，不能用最终表覆盖初始表；无需把台账塞入媒体正文。读一项初始资产、一项后补资产和一个状态变体，从源依据追到完整设计、当前ID、分镜使用及文件名，确认资料在独立目录内可读；有相应类型才检查，不造假样本。

## 后续生图如何接续

后续生产以**最终当前总库决定身份、设计与状态**，以**采用分镜决定实际用途和第一帧状态**，以**v7图片目录决定本次导入图片范围与精确文件名**。三者有冲突先回查源与采用版本；不能重新从正文造一套并行资产表，也不能让图片清单反向删掉完整上游账。

命名链继续是 `assetId → name/key → importName → @[importName+type] → 类型中文-importName.png`。同一资产的真实成图将来沿用该导入名和文件名；内部身份名可能带标点，不能直接套另一个Skill的原名命名规则而破坏v7引用。真实图片替换白图后，须重核图片质量、实际尺寸/可用性、文件名与引用及平台导入；白图的专用尺寸递增规则不能套作真实成图规格。

完整总库不等于每项都要生成图：默认图像队列先对应实际图片引用；扩大到整库或追加开场图、多机位、服装/形态等，按后续明确范围和同一总库登记。新的正式状态经核源、核重、采用后按原回补闭环更新真实消费者，不偷偷增图、换名或合并身份。

已经开始生图后发现漏项或修订，交新版接续资料并在交接清单附增量：所据旧/新总库与采用稿/图片目录版本、资产ID及单项版本、精确文件名、受影响单元，以及新增、修订、复用或本次不再使用的原因。由同一当前总库派生，不再建手工命名权威。接收方先按ID和设计版本对账：无关新增不使原图失效；已改设计只将真实受影响项及其衍生项标待复核，兼容的旧图保留采用依据；本次不再引用的项移出本次队列但保留历史图片，不删除旧成果、不自动覆盖或全库重生。资产版本变更不等于已经授权新增生图或重新采用。

后续生图工具收到完整接续资料时，先读取该最终总库、实际采用分镜和配套图片目录，再处理上述增量；不能退回只扫MD三行的普通洗后剧本模式。仅收到三行时可按原清单制作，但如实说明未审完整分镜补漏。缺失的正式项先回补本库并更新真实消费者，未登记的候选只留待补，不伪造ID或队列已齐。

可借鉴资产生图流程的身份锚点、场景拓扑、版本层/状态层、参考图职责及真实像素复核。其模型名称、固定电影风格、人物七视图、固定画幅、评分门和逐图审批不是本分镜Skill的默认规则；后续生图技能按项目需求单独确定。总库文字设计采用、候选成图、正式成图和用户认可分别记录，不能相互替代。
