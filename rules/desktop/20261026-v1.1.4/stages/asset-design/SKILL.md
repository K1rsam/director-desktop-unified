# 完整资产设计、采用与供料

本阶段按[视觉基准](../../references/visual-baseline.md)在同一次方向决定中核画风/造型、渲染/着色、材质、色光、画幅及局部例外；已有采用基准直接继承，完整设计与后续供料引用同一版。

仅已启用并锁定季模式时，按[季范围合同](../../references/season-scope-contract.md)限定本次设计用途；未来独立形态和后续资产只留导航，不提前完整设计或生成图片。普通全剧沿既定范围与首次使用次序推进，文字设计不自动授权生图。

本版还按[桌面生成链第2至3节](../../references/desktop-generation.md)区分当前可用形象、背景证据和父设计来源。多层父链按真实直接依赖承接，基础场景与事件状态分开；同物道具的文字设计需核源协调，不自动加图片依赖或当作同一物。供料用途放工作资料，不向本地bundle新增未经支持的Rust字段。

读取统一总库当前快照、阶段1全剧导航/源事实及已确认方向，再读[前期质量合同](../../references/preproduction-contract.md)和[基础资产形象设计](../../references/foundation/asset-image-design.md)。确认前只准备影响方向的候选；确认后按共同母设计和各集真实依赖完成完整设计、跨项复核与采用，再提炼短卡。当前集依赖就绪即可开工，远期独立设计按首次使用推进，不等待全剧核心项统一齐套。不要求每项另起AI调用，但应有的设计与核源工作不能省略。

源有系统时先读其同版[呈现决定](../../references/system-presentation.md)，据此设计载体/化身并保留叙事身份与可见域；不由资产岗默定面板或角色。纯声源不强建图片，系统音不因可见化身改成现场对白。

每项卡保留稳定身份键、正式名、类型、来源、基线/父子状态、实际适用集场和三类分区：

- **源事实**：原文明示的身份、外观、功能、形态与必要空间关系，带源引用。
- **采用设计**：为制作补足的识别特征、材质/配色、服装及空间地标，记录依据与决定范围；不能增加身份、能力、亲密关系或剧情结果。
- **开放项/未知**：可由本集表现自由设计与真正缺失的硬依赖分别记。方向/设计候选不能假称用户已采用。

无外观信息时按已确认方向补足制作所需完整设计，明确它是设计选择；按角色层级和识别差异设计，不让所有角色同美貌、同丑化、同服装模板。人物/兽类外形、服装结构、场景拓扑/地标/表演区、道具结构与操作条件按类型落实，逐条核lockedFacts，不从名字猜物种或功能。普通表情与姿势归第三阶段，资产设计不冻结机位、瞬时Q形变或身体动作。独立兽形、召唤物与本人变体依原关系区分；同一形貌不证明同一身份。

完整设计及其源约束、补足清单、适用时点和复核依据保存在 `design.full`，采用后提炼 `design.text`。短卡必须能回查同版本完整设计，不能把短卡原样复制再改字段名当完整设计。变体实际继承了其它采用设计时，另记 `design.dependencies` 的稳定ID与所据版本；身份家族/parentId与设计依赖分别保存。来源卡变更须沿真实依赖核派生设计及其消费者，不能只检查同一个ID。

使用 `UNADOPTED / TEXT_ADOPTED / REFERENCE_ADOPTED / STALE` 记录设计状态。未读像素用 `NO_PIXELS_READ`；文字采用不等于图片存在、已上传或图像一致性通过。源特征、方向或采用设计实质变化时标受影响卡待复核，仅定位已消费它的分集/工作包，不重做无关成果。

原有正式名字逐字保留。v7 在统一总库中另存 `importName`，内部 `name/key` 单行保留原标点，`originalName` 继续保存源称呼；三行、@ 和 PNG 均从同一安全名映射生成。按 Python `isalnum` 核安全字符，同类重名及文件名冲突必须明确解决，不能把变体并回基础。使用 `init/apply/prepare-import` 写新快照，不手改总库或另建命名权威表。语义分类CH/GROUP/BEAST/LOC/PROP与最终SC/CH/PR引用后缀是不同层，序列化映射单列，不能为后缀改变主体身份。

总库分配 `placeholderOrdinal` 稳定编号，白图边长为 `300+编号`；新增只追加、修订保留旧号，不能随排序重编。阶段二可先预留文件名和编号，逐集试导或最终打包时再生成纯 PNG 白图；文字卡采用与白图存在、真实图片制作、用户认可分别记录。详见[灵墨 v7 合同](../../references/lingmo-v7-contract.md)。

第三阶段收到必要源事实/导航、当前状态、采用短卡及对应完整设计的明确入口；按[供料合同](../../references/context-and-dispatch.md)，主创、整编及非作者复核实际读取本集所用正式视觉资产的完整采用设计，短卡只作定位和投影，不以“短卡足够”跳过读取。只携相关设计，不反复携带无关长文，也不能让各路另造同一空间。场级目录不是本单元全部入画清单；仅被提及、纯声音、现实实体、屏幕/回忆/未来图示分开。纯声音不自动配图；瞬时 Q 版和幻想表演可在 `visualSubjectBindings` 用 `assetKey:null` 保留正文表现，不强造卡。确需独立可复用状态或参考图时，按同一回补流程正式登记。

缺料回报须定位集/场/工作包、资产键、用途和源锚。已知卡可补当前需要的文字设计；新源冲突回阶段1定位，不能由设计猜故事。到达补料不等于已实际消费，消费后再关闭相应缺口。普通局部补料不扩成全剧资产生产。

按[统一资产合同](../../references/asset-registry-contract.md)落实回补：主代理核同物异名、源漏拆与导演设计，用assets.mjs的add/revise/reuse登记；第三阶段不得另建权威库。补来的正式视觉资产也先完成设计、核源采用和短卡投影；既有完整设计仍有效就直接复用，不机械重写。阶段二未有单元时用asset-design和空uses，不虚构消费；第三阶段已有缺项必须记录真实使用位置，等作者更新画面、绑定并产生当前消费回执才关闭。

本阶段复核全剧依赖/首次使用安排，并逐集交付当前所需的已采用设计；不把单集可开工写成全剧所有设计已完成。普通对象按[分流合同](../../references/asset-registry-contract.md#普通制作对象的分流)在原岗位完成，瞬时状态和持物不反向重做稳定母卡。用户未指定关键设计不等于免做设计，也不等于全部待用户审批；普通设计由总导演按既有授权采用。真正缺关键依据或未解决的设计矛盾只阻塞真实依赖，缺图片不阻塞文字制作。按[资产交接合同](../../references/asset-handoff.md)保留初始基线、当前全库、完整设计与后续补项。
