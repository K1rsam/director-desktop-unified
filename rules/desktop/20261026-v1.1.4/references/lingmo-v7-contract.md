# 灵墨 v7 输出与素材合同

本合同用于新剧本的 `bundle.exportProfile:"lingmo-v7"`，与[成果数据合同](data-contract.md)、[统一资产合同](asset-registry-contract.md)合用。省略 profile 或显式 `series-single-zone-v1` 只用于旧格式回查；未知 profile 拒绝。迁移生成新版本，不能把旧稿核验结果称为 v7 交付。运行只用本包 Node.js 24+、Python 3.9+ 标准库，不调用其他 Skill、旧项目或图像服务。

## 1. 创作范围与兼容边界

保留全源接入、四岗位、六类方法、整集整编、精修、内容独审、实际跨集核对及资产回补。新剧本沿用现行原场、事件和工作包边界；格式升级不扩大跨场能力。已有跨场完整采用稿继续用既有保真转换入口，不能为此输出层重拆。

包内创作原稿仍保留历史的“内部总长整数终点”说明。**仅当采用 v7 时，该格式条件由本合同第 4 节替代**；原声自然性、动作相位、因果、空间、情绪回报和合法切点照常核查。不要为了满足旧整数门修改已成立的小数时间线。

旧 80 集转换的冻结资产范围仅适用当时该稿。新项目有据的直播手机等漏项继续核源、核重、立项、补卡并实际消费；不能以旧表不含手机为由跳过回补。

## 2. 内部身份、图片引用与安全名

`name/key` 是内部正式状态名和逻辑键，保持单行、保留原标点及已有身份；`key=name+type`，`type` 为 CH/SC/PR。`originalName` 保留源称呼，稳定 ID、源事实、家族关系及设计不被改名覆盖。v7 另存 `importName` 和 `placeholderOrdinal`，统一总库为 `importProfile:"lingmo-v7"`。

安全导入名按 Python `str.isalnum()` 逐字符规则核验，非空且不是占位词“无”；结构分隔符不进入安全名。清洗发生空名、同类重名或 NFKC+casefold 后文件名冲突时显式解决，不猜身份、不合并状态。场级三行、@ 令牌和 PNG 文件名只使用 `importName`；原声与导演正文不全局替换称呼。唯一映射为：

`assetId → 内部 name/key → importName → @[importName+type] → 类型中文-importName.png`

映射由当前总库投影生成。CH/SC/PR 对应 `角色/场景/道具` 文件名前缀；例如内部 `值守者·面罩CH` 可映射 `@[值守者面罩CH]` 和 `角色-值守者面罩.png`。不要另建可独立编辑的命名总表。

每个 v7 单元必填 `imageBindings` 内部键数组，可空、不可重复、最多 30 项，且是 `bindings` 子集。它只选本段实际需要参考图的现实、媒体或明确视觉主体；不能从逻辑绑定或场级目录整表复制。

| 记录 | 用途与图片边界 |
| --- | --- |
| `bindings` | 保留场景、道具、现实人物、媒体主体、正式视觉实体和实际声源的逻辑核验；v7 的 30 项限制仅计图片。 |
| `voiceBindings` | 按人声原句绑定声音身份。纯画外声、OS、人声VO不自动加图；同段入画另选。系统音不虚造人物图；有据声音事件不要求CH或voiceBindings。 |
| `visualSubjects:[{name,domain}]` | 保留 native 的 subjective/prospective 域，不往此结构塞资产字段；实际 Q 版/幻想仍须写入画面和演出。 |
| `visualSubjectBindings:[{name,domain,assetKey}]` | 有视觉主体时逐项对应上项。`assetKey:null` 表示正文表现，不强立卡；非 null 是明确已采用 CH 的内部键并进入逻辑绑定，需图时再选入 `imageBindings`。无视觉主体时可省略。 |
| `mediaSubjects` | 屏幕、照片、历史插入保留域和源锚；需要参考图时明确选择，不能冒充现实出场。 |

场的内部 `bindings` 仍等于本场各单元逻辑绑定并集；v7 **输出**三行等于本场各 `imageBindings` 并集。每片段只引用自己的集合，同一图片在该片段的三个资产标签内合计出现一次。总库、场目录和单元范围可以不同。未知键、重复键、错状态或当前映射不一致须返回坐标；自由文本实际用途仍须读稿核验。

## 3. 正文结构与字段保留

按[视觉基准](visual-baseline.md)先核完整采用对象与各集settings一致，再逐段完整合成。新输出不得只核visualStyle非空；自定义文字、声音/字幕决定、本段unitDirection及局部幻想边界完整保留，不注入未采用默认风格。独立回读核实际通用头，内容充分性另读稿判断。

一个文件仅一个 `**【标准化剧本】**` 区，按源顺序保留原集号、原场号。原场号含 `@[` 或与该标准区标记相同时返回坐标，不能静默改号、添加图片或再开一个标准区。每场只有一组 `场景：`、`人物：`、`道具：` 三行；一个原场可有多个片段。每个视频单元对应一个片段，内部从 0 连续计时。

片段顺序：`片段N`、`时长：N秒`；`[通用提示词]`；`[场景]`、`[本单元道具]`、`[本单元出场人物]`；`[本单元光影]`、`[人物状态与站位前提]`；逐镜 `分镜N｜A-Bs｜Cs`。每镜字段顺序为 `机位/运镜`、`画面`、`光影`、`声音`、`台词`、`转场`。

@ 只嵌入三个资产标签对应行。空类保留合法声明；不输出顶部 `引用：`、独占日夜内外行、`片段正文：` 或 `[主观视觉主体]`。日夜内外写进 `[场景]` 描述；删除主体标签不删除已采用的 Q 版、幻想、变身画面。

分段首态与单元自身光影/首态不同的，补 `[单元光影]`、`[单元起始状态]` 保留原字段。对应首镜前以分段标题、分段演出、光影承接、人物状态、分段结束状态标签保留分段资料，尾部 `[结束状态]` 保留单元出口。正文原本含 `@[` 等导入令牌形状时返回坐标，由采用阶段明确处理，不能静默把原文当新增图片或改字。

| 采用字段 | 必须保留的正文内容 |
| --- | --- |
| 项目 `visualStyle/prohibitions`、`unitDirection` | 通用提示词中的画风、画幅、项目禁止项及完整单元演出指令；不注入默认自然 3D 风格。 |
| `scene/dayInterior`、`props/participants`、媒体与视觉表现 | 对应资产/状态描述及实际画面；安全名仅用于目录和令牌。 |
| `lighting/initialState/exitState` | 单元光影、入口状态与完整结束状态，不能只保留开场。 |
| `segments` | 对应首镜前的分段演出、光影、入口及出口，镜头完整同序分区。 |
| `camera/picture/lighting/sound/dialogueParts/transition` | 每镜全部六项，保留多行文字与原顺序。 |
| `soundEventDecisions`及presentation为声音事件的片段 | 仅按[源绑定合同](desktop-adapter.md#源绑定声音事件)有据处理非人声描述；声音栏追加“起点–终点秒｜非人声：delivery”，可与对白同期。仅事件的镜头台词为无；原quote/标签/区间仍留结构化稿追溯，不朗读、不放hash/审核理由进媒体正文。 |
| 原句、`channel/kind/cue`、`performanceCues`、`presentation/delivery/voiceStart/voiceEnd` | 原说者、逐字文本、声道、声型与原声窗保留。新生产用`generationTextVersion:"voice-delivery-v1"`：原始cue/performanceCues完整留源中，不自动进入生成正文；真正发声/动作提示由作者按说者与句内位置落实delivery/picture/sound，后期说明只交独立文件，整编与非作者逐项回读。历史无此策略稿保留原提示投影回查。非词人声不能吞成“无”，不把提示读成台词。 |

第三阶段先核结构化字段到完整采用正文的映射，再保存该版本的正文和预览实际字节。后续导出只加结构外壳与令牌；去掉新增 @ 后的冻结正文必须逐字节一致。历史原文入口只允许已确认的 `[主观视觉主体]` 整行删除；本包新生产不能借此删除创作。字节相等不证明更早字段映射没有漏项，仍须字段级和正文内容复核。

通用提示词的共同职责是“当前项目风格/画幅与有效输出限制＋本单元演出总指令”，不是统一长度模板。按实际采用的visualStyle、prohibitions和unitDirection完整映射，不从其它作品移植画风或给旧稿补一套默认前缀。相同限制不在每镜重复；已采用的有效细节不能在导出时摘要删减。与其它实现比较时同时记录源/方向/模型、创作规则版本、实际供料、采用稿及导出版本：旧稿不会因Skill升级自动改写，文本长度相近也不证明声画执行相同。

## 4. 精确时间与外层容器

实际时间线是所有镜长的精确和，内部镜窗、声窗保留最多 9 位小数，不取整、不改词或语速。v7 外层时长为 `max(4, ceil(实际总长))`，按整数时间刻度运算；实际总长及外层容器均不得超过本项目已确认的 15/30 秒上限，超限拒绝。

| 实际总长 | v7 外层 | 处理 |
| --- | ---: | --- |
| 29.1 / 29.4 | 30 | 内部全部保持，不补演出。 |
| 3.2 | 4 | 保留实际短尾；创作阶段优先自然联排，不拖演。 |
| 30 | 30 | 保持。 |
| 30.000000001 | 拒绝 | 回到合法局部切点重排，不截成 30。 |

`series-single-zone-v1` 仍核其原整数总长要求，不由新模式静默改写旧输出。15 秒项目不因灵墨支持 30 秒而放宽。

## 5. 配套目录与白图

v7 `export` 同时写 MD 和资产目录；默认目录为 `${output}.assets.json`，可用 `--assets-index FILE` 指定。`verify` 必须核同一 MD 和目录，不能单核 MD 宣称成套。目录版本为 `lingmo-v7-assets-v1`，`assets` 每项含 `id/assetRevision/name/type/token/filename/placeholderOrdinal`，其中 `name` 是 `importName`。绑定 hash 只用于证明配套文件一致，不证明内容审或平台解析通过。

目录默认覆盖本次全部采用的图片引用；纯逻辑声源不生成白图。明确要求整库素材时，另据当前总库确认正式图片项范围，不猜哪些声源有图。`placeholderOrdinal` 从 0 起持久分配，边长 `300 + ordinal`，最高 6000；新增只追加，不重排、复用旧号。修订保留原号；不同 PNG 的尺寸及 MD5 必须不同。

包内 `make-white-placeholders.py --index JSON --output-dir DIR [--verify]` 生成或只读核验白图。新目录排他创建，已交付版本不覆盖；零图片范围可为空目录。目录仅放 PNG；JSON、日志和导入说明放外面。白图只证明占位文件存在，不证明真实视觉资产已生成或用户认可。

## 6. 阶段门与交付证据

1. 接入保存 v7 profile，按实体和动作依赖查漏，保留源事实/设计区别。
2. 资产阶段按[前期质量合同](preproduction-contract.md)完成完整设计、复核采用与短卡投影，在统一总库确定安全名及稳定编号，不把全图齐备设为文字制作前提。
3. 每集处理回补后，对当前总库 `sync → check → export → verify`，读实际稿核正文—图片引用；保存采用正文、v7 预览、配套目录和当前证据。独审按现行逐集机制执行。
4. 全剧用当前总库重新 sync，核完整源覆盖、内容复核闭环和实际跨集承接，合并后核 MD/目录并生成、验证白图。

最终默认一份版本化 `全剧_灵墨v7.md`、同版本纯 PNG 文件夹及其 ZIP，另附简短配套说明。按[完整资产交接合同](asset-handoff.md)将初始/最终总库、完整设计、源/方向依据、最终采用稿、图片目录和消费回执另放同级接续资料；不塞进图片目录或媒体正文。分集旧预览及冗长内部审计留工作区。上述本地检查完成只能标“本地上传包准备好”；本次文件实际上传灵墨后的反馈另记，旧 v7 实测和本地 PASS 不能替代。

交付前必须执行[中文命名、字段观测与逐段引用核验](lingmo-field-budget.md)；既有引用有效不等于应有引用齐全，容量样本值不作为硬上限，本地通过不替代新文件平台实测。
