# GPT_IMAGE25_ASSET_WORKFLOW V1.1.2

## 1. Skill 目标
本 Skill 用于 Codex 驱动 AI 短剧的电影风格视觉资产生产，目标出图模型为 **GPT-image-2.5**。

目标型号不等于实际调用型号。记录实际工具与可核实的型号；无法核实时如实标注。用户已允许的替代工具沿用，不重复询问，也不得宣称型号已验证。

核心目标：
1. 剧本优先，资产不改戏。
2. 人物、场景、服装、群演、开场参考图具备连续性与可复用性。
3. 资产图直接达到成片级电影风格，不依赖后期调色。
4. 资产必须服务后续 AI 视频生成，优先稳定、可扩机位、可种人物、可接戏。
5. Codex 的第一生产产物是可直接复制到 GPT-image-2.5 的成品提示词；随后可继续自动出图。

## 2. 总执行流程

### 分镜资产接续模式
收到已采用分镜及完整资产接续资料，或要求按分镜查漏/接续已有图片队列时，先读[分镜资产接续模块](modules/22_storyboard_handoff.md)：最终当前总库定身份与完整设计，采用分镜定实际用途，配套图片目录定范围与精确文件名；已有队列按稳定ID/设计版本做增量对账。此模式优先于下方普通三行模式，不重新造表、换名或全库重生。带 `productionScope` 的季模式只按显式 `series-image-queue-v1` 建立任务；完整源供核源，每批派发前必须实际运行模块22的本地校验器，缺范围或越界拒绝，不回退全剧清单。只维护/审计不启动生图；缺资料的范围如实留待核。

### 结构化三行资产清单模式（洗后剧本默认）
当每集正文中已经按场次提供以下三行时，以它们作为“生成什么、如何命名”的权威资产清单：
```text
场景：南疆官道日间状态
人物：李安默认状态、刘舞伶默认状态
道具：素白折扇墨字面状态、鎏金黑漆马车状态
```

执行规则：
1. 从第一集到最后一集顺序读取；每个 `场景：` 开启一条场次资产记录，紧随其后的 `人物：`、`道具：` 归入同一记录。
2. `人物：` 和 `道具：` 默认按中文顿号 `、` 拆分；兼容逗号或分号，去除首尾空格，但不得改写资产名称。
3. `道具：无` 表示该记录不生成道具图片，不得创建“道具-无.png”。人物或场景字段为空则视为结构错误。
4. 清单原文中的“默认状态、朝服默认状态、夜间状态”等状态词属于资产身份和文件名，不得擅自删减、改写或合并。
5. 同类别、同名称、同状态在全剧只生成一次；后续集直接复用。名称相同但状态不同，必须作为不同资产分别生成。
6. 资产首次出现的集数和场次用于回读对应正文，补足脸、服装、空间、材质和道具细节；正文只提供视觉证据，不擅自增加清单之外的正式资产。
7. 生成队列按首次出现顺序建立，并保留每项被哪些集、哪些场次调用的内部映射；调用映射不进入最终图片文件夹。
8. 生图前验证 `场景／人物／道具` 三类行是否成组完整。出现缺行、错序或无法归属时先报告结构问题，不得静默漏项或猜配。
9. 文件名直接使用清单中的完整资产名称并加类别前缀，例如：
   - `场景：皇宫金銮殿夜间状态` → `场景-皇宫金銮殿夜间状态.png`
   - `人物：李安默认状态、老皇帝默认状态` → `角色-李安默认状态.png`、`角色-老皇帝默认状态.png`
   - `道具：帝王白玉杯状态` → `道具-帝王白玉杯状态.png`
10. 检出这种三行清单后，不再重新从整本正文推测一套并行资产清单；只有用户明确要求补漏审计时，才另行检查正文中未列出的候选资产。

### 完整剧本模式
1. 完整读取剧本，不立即生图。
2. 分析题材、时代、叙事气质、人物层级、场景结构。
3. 提供 3 套基础视觉方案；每套附 2–3 个最终电影调性。
4. 每套同时给出人物视觉前缀示例与场景视觉前缀示例。
5. 用户确认视觉方向。
6. 生成项目母视觉圣经；必要时建立阶段子视觉圣经。
7. 优先检测并读取每集的结构化 `场景／人物／道具` 三行清单；仅在不存在该结构时，才从正文识别人、服装、群演、场景、状态/版本和关键道具。
8. 识别冲突：可解释的变化拆版本；不可解释的冲突进入待确认表。
9. 输出简化资产制作需求总表与建议制作顺序。
10. 默认等待用户确认；用户明确“直接跑/连续跑完”时可跳过确认 Gate。
11. 按资产依赖关系分批生成内部使用的 `.md + .txt` 成品提示词。
12. 每条提示词进入质量 Gate，不合格自动重写。
13. 用户确认或进入连续模式后，调用 GPT-image-2.5 出图。
14. 默认每项先生成一个候选并目视复核；必要返修或用户要求探索时才追加。正式采用按第 15 节的用户确认或明确委托执行。
15. APPROVED 成图反向分析，更新视觉锚点摘要。
16. 后续执行换装、多机位、状态版、开场参考图、剧情图。
17. 将最终确认的角色、场景、道具图片按第 19 节规则汇总到一个扁平交付文件夹；不交付内部提示词、台账或质检目录。

### 单资产模式
用户点名人物/场景时：
- 若项目视觉圣经已存在，直接继承。
- 若不存在，先询问视觉风格与参考图。
- 可在内部生成模块化 `.md` 与可直接复制 `.txt`，但默认不把它们放入最终交付。
- 通过质量 Gate 后可继续出图。
- 最终只交付一个包含图片的扁平文件夹。

### 批量连续生产：统一执行规则
已确认范围、风格并获准连续生成后，必须读取 [批量生产模块](modules/21_batch_production.md)：
- 默认每轮并发 8–10 个独立生图任务；受工具能力或真实服务限制时降低，记录原因。
- 新图与必要返修滚动混排，优先解除母版依赖；批号只用于归档，不等整批返修完才开下一批。同脸、同景衍生仍等待 APPROVED 母版。
- 同一缺陷连续两次返修未改善，先诊断并换方法；难项留在修复队列，其它独立项继续。重试次数不构成降标、放行或漏项依据。
- 同人换装保留第 4 节原像素合成；普通新人物默认整板一次生成，不额外拆图。只补当前剧情或清单确需的状态、机位。
- 缓存已确认设计和锚点，只读取当前项所需证据；保存逐项回执，按唯一资产队列统计。候选、待修、在途、正式采用和附图分开报告。
- 连续生成不自动授予正式采用权；已有明确委托则按委托范围自主确认，不逐批重复审批。暂停、恢复与最终核对见批量模块。

## 3. 高优先级硬规则

### 3.1 剧本优先
- 剧本明确内容必须执行。
- 普通影视美术细节可自动补全。
- 涉及人物核心身份、空间拓扑、关键道具、主位、进出口、后续接戏的缺失信息，如果存在多种合理方案，必须标记待确认。

### 3.2 项目视觉风格
- 资产直接达到最终电影风格，不预留后期调色环节。
- 母视觉圣经 > 阶段子视觉圣经 > 当前场景情绪。
- 电影感来自：构图、空间层次、光影塑形、最终色彩、材质、摄影语言。
- 禁止用“加颗粒、压暗、强虚化”代替真正电影感。

### 3.3 AI 视频友好
人物、场景、开场参考图默认：
- 结构清楚。
- 不做过强浅景深。
- 不做明显前景遮挡。
- 不做过度复杂、难连续复现的纹样。
- 不做不可解释的抽象光影。
- 不牺牲连续性换单张冲击力。

### 3.4 最终交付与文件名前缀
- 默认只向用户交付一个扁平图片文件夹，不建立人物、场景、道具子目录。
- 文件夹中只放最终确认的角色、场景、道具图片；不放 `.md`、`.txt`、`.csv`、`.json`、提示词、台账、日志、质检报告或中间候选目录。
- 角色类图片文件名必须以 `角色-` 开头，例如 `角色-小明.png`。人物身份板、服装版本、年龄阶段、特约和群演合板均归角色类。
- 场景类图片文件名必须以 `场景-` 开头，例如 `场景-森林.png`。场景主资产、昼夜/天气状态、多机位、开场首帧参考图均归场景类。
- 道具类图片文件名必须以 `道具-` 开头，例如 `道具-宝剑.png`。武器、器物、载具及其他独立制作的物件资产归道具类。
- 类别前缀必须位于文件名最前面；`CHAR_`、`SCENE_`、资产编号或版本号只能放在前缀之后。
- 同名资产需要区分时，在名称后追加必要的服装、状态、机位或版本信息，例如 `角色-小明-服装02.png`、`场景-森林-夜间-机位A.png`、`道具-宝剑-v2.png`。
- 结构化三行清单已给出完整名称时，优先原样使用清单名称，例如 `李安默认状态` 直接命名为 `角色-李安默认状态.png`；不得再自动缩写为 `角色-李安.png`。
- 最终图片默认使用 `.png`；用户明确指定其他图片格式时才改变。
- 混合画面按资产的主要用途归类；开场图和以空间连续性为目的的剧情图归场景类。无法判断主要用途时才询问用户。

## 4. 人物标准资产板：最高优先级永久锁定
任何后续人物模板都不得改变此版式。除群演合板外，所有单人人物资产板严格使用 1:1 正方形画布。

### 上排 3 个锁脸视图
1. 正脸。
2. 向右纯侧脸。
3. 向右约 45° 的 3/4 脸。

规则：
- 不穿衣服，只显示头部、颈部、肩部/少量锁骨。
- 男性可略多露肩颈与少量上胸；女性控制在锁骨和肩部范围，保持中性资料板属性。
- 无饰品、无遮挡；不戴眼镜、帽子、耳饰、项链、头饰等。
- 发色、发长、分缝、刘海、卷直状态、发际线、整体轮廓必须与正式发型一致；只允许轻微拨开挡脸碎发。
- 发型不依赖遮耳时，尽量露出耳朵；核心造型遮耳时保留正式结构，但必须能判断耳位、下颌与侧脸轮廓。
- 表情中性、气质存在，不做笑怒悲等明确表演。
- 三个头部本体尺寸一致、眼睛高度尽量对齐；高马尾、角、蓬松卷发等可自然超出。
- 默认纯白背景 + 白棚柔光；浅色轮廓与背景粘连时只允许极轻微灰白分离。

### 下排 3 个全身服装视图
1. 正面全身。
2. 向右侧面全身。
3. 背面全身。

规则：
- 从头顶到鞋底完整入画。
- 双臂自然下垂、手指自然放松，不拿任何道具。
- 正面、侧面、背面人体本体同身高、同脚底基线、同人体比例。
- 特殊长裙、拖尾、披风、翅膀、长发、角、机械附属可自然超出，但人体比例不变。
- 脚部默认标准化；特殊鞋型/足具可轻微调整，但不破坏三视图对齐。
- 正面全身和向右侧面全身的面部必须用纯白色不透明涂抹完整遮挡五官：保留头型、耳朵、发际线和发型，白色只覆盖面部区域；背面全身保持自然后脑与发型，不出现白斑。
- 发型核心结构与上排完全一致；仅为展示领口/背部结构时可轻微整理，不得换发型。

### 右下上半身服装展示位
- 正面上半身服装展示。
- 面部必须用纯白色不透明涂抹完整遮挡五官；白色只覆盖面部区域，保留头型、耳朵、发际线和发型。
- 明显大于下排全身人物，但不锁死放大倍数。
- 根据服装结构裁到胸口以上或腰部以上。
- 尽量完整包含双臂与双手；双手自然，不拿道具。
- 与全身图保持同样质感、清晰度、材质，不单独做更锐更“微距”的风格。

### 整体版式
- 7 视图。
- 除群演外，单人人物板严格为 1:1 正方形。
- 纯白画布，靠留白自然分区。
- 无边框、无分隔线、无标题、无编号、无文字、无 Logo。
- 白棚柔光标准资产光。

### 同角色不同服装：分步生成与原像素合成
- 禁止把既有完整人物资产板作为整板图改图底图，也禁止重新生成上排 3 张大头。
- 第一步：参考角色原始身份图和新服装设定，独立生成 1:1 新服装板的下排 4 个服装视图，并为上排保留与 APPROVED 身份母版完全一致的 3 个槽位。
- 第二步：从该角色 APPROVED 身份母版裁切上排正脸、向右纯侧脸、向右 45° 的 3/4 脸，以原始像素 1:1 复制到新服装板上排对应位置。
- 复制时禁止缩放、重采样、AI 重绘、修脸、锐化、调色、补帧或添加生成式蒙版；所有服装版本上排必须与身份母版逐像素一致。
- 下排仍执行白脸规则：正面全身、侧面全身和放大上半身纯白遮脸，背面保持自然后脑。

## 5. 群演/小配角合板
- 默认使用 16:9 横向画布。
- 一张最多 6–8 人。
- 一字排开，正面、全身、纯白背景。
- 不加文字、名字、编号。
- 纯群演：标准化正面站姿；小配角合板允许轻微姿态差，但不得遮挡服装轮廓。
- 同组织/同职业保持统一服装体系；颜色、层级、配饰可轻微变化；剧本明确统一制服时严格统一。
- 保证每个人一眼可区分，但不破坏同群体统一审美。
- 自动控制自然年龄、身高、体型差；不出现“同脸换衣服”。
- 后台每人建立独立子编号，如 `EXTRA_001_01`。
- 后续升级重要角色时优先继承原核心特征，必要时在不改变身份的前提下精细升级。

## 6. 场景主资产硬规则
标准场景资产首图：
- 16:9。
- 绝对无人：不出现人物、群演、剪影、远景人影、玻璃/镜面/水面中的人物倒影。
- 场景全部高细节，不因戏份短而简写。
- 前景/中景/后景必须明确分配。
- 明确门窗、墙体、楼梯、通道、地面、墙面、天花、核心家具、固定陈设、表演区、留空区、安全区。
- 默认不出现明显前景遮挡。
- 基本全清晰，不做明显浅景深。
- 控制广角畸变，不做鱼眼感；门框、墙线、家具不能明显拉伸。
- 标准场景资产优先稳定垂直线与水平线，不做无依据荷兰角。
- 普通室内/街道优先接近成人视线高度；大型广场/宗门/建筑外观可适度低机位或轻微俯视。
- 构图先保证空间结构，再适度电影化。
- 四周保留合理镜头边缘安全区，关键门、通道、表演区、核心家具不贴边。
- 人物表演空间必须真实、可用；不为了表演做成不自然大空地。
- 对话/走位/打斗高频场景控制布景复杂度；展示/建筑外观可更丰富，但禁止堆物件。
- 资产直接达到最终电影色彩与光影质感，不依赖后期调色。

### 6.1 材质
采用影视美术级细化：
- 木材：纹理、表面处理、半哑光/抛光/旧蜡、边角磨损。
- 石材：粗糙度、切割、抛光、风化、反射。
- 金属：拉丝、磨砂、氧化、抛光、旧化。
- 玻璃、皮革、织物、漆面、陶瓷等写明真实表面特性、新旧程度、反光特性。

### 6.2 使用痕迹
- 真人/仿真人现实题材：按空间身份加入适度真实使用痕迹。
- 豪宅、酒店、医院、实验室等高维护空间更整洁，只保留合理痕迹。
- 禁止为了“真实”统一做脏、做旧。

### 6.3 尺度真实性
- 真人/仿真人项目强制检查门窗、桌椅、楼梯、走廊、层高、家具与人物比例。
- 3D/动画/高幻想可适度夸张，但角色必须能正常使用空间。

### 6.4 灯光
- 允许电影化虚拟补光、轮廓光、顶部柔光等，但必须服从空间层次与项目视觉圣经。
- 禁止多方向乱打光、毫无逻辑局部高亮。
- 默认中等以上可读亮度；特殊题材可更暗，但关键空间结构仍可辨。

### 6.5 文字
- 短而关键的门头/牌匾/店名可直接生成。
- 长文本、密集文字、复杂排版不依赖标准场景资产，转为独立文字/道具资产或后处理。

## 7. 场景连续性与版本层
### 不可变层
- 空间拓扑。
- 墙体、门窗、楼梯、通道。
- 核心家具、固定陈设。
- 主材质。

### 版本层
- 装修变化。
- 时代变化。
- 大规模破损 / 修复。
- 长期结构状态变化。

### 状态层
- 白天 / 夜晚。
- 天气。
- 灯光开关。
- 烟雾。
- 临时道具。
- 轻微脏污 / 少量破损。

核心重复场景完整三层管理；普通场景适度简化，但场景描述本身仍然保持高细节。

## 8. 多机位
- 按场景复杂度自动规划 2–N 个真正有用机位，不为凑数量生成无价值机位。
- 记录每个机位可见的门窗、通道、核心家具、表演区、人物进出口、前中后景。
- 同一状态版本内，所有机位必须保持相同时间、天气、灯光开关、色调、环境状态，仅机位变化。
- 单机位错误优先只修当前机位；若暴露母场景拓扑错误，先修母场景锚点，再重做受影响机位。

## 9. 新场景开场参考图 / 视频抽卡首帧参考
### 触发
- 剧情真正切换到新空间或新的子空间时触发。
- 同一空间只换机位不触发。
- A→B→A：若人物、服装、时间、环境、站位、剧情起点变化，重新生成；完全一致可复用。

### 依赖
默认必须有：
- APPROVED 场景资产。
- APPROVED 第一帧出场人物资产。
- APPROVED 对应服装版本。

如果第一帧手持道具未做正式资产，可按剧本临时生成，不阻塞开场图。

### 画面规则
- 默认全景 / 大全景优先。
- 小空间物理限制严重时才允许中全景；不直接做中景或近景。
- 不强制核心人物脸在大全景里清晰可辨。
- 纯干净画面：不加名字、编号、箭头、站位线。
- 只放第一帧已经在场的人物；后续进场人物不提前种进去。
- 站位必须以剧本为第一依据；剧本未写死时依据人物关系、对白、动作、空间、进出口合理补全；无法可靠判断且影响接戏时才询问。
- 剧本关系绝对优先，在不改变剧情关系、权力关系、动作起点的前提下做电影化优化。
- 复杂姿态可简化，但不改变姿态类别：坐仍坐、跪仍跪、靠墙仍靠墙、躺仍躺。
- 表情整体压低强度，优先稳定；核心人物视线按剧本，普通人物/群演尽量简化。
- 核心人物尽量不被遮挡；配角可轻微遮挡；群演可有层次遮挡但不得挡住关键人物。
- 不主动为了下一步运动方向额外留空间；只保证当前第一帧站位与空间关系正确。

### 机位
- 优先复用已确认场景机位。
- 若都不适合，新建 `OPEN_CAM`，只能改变机位，不得改变母场景拓扑。
- `OPEN_CAM` 经确认且具备复用价值时可升级进入正式机位库；否则保持开场专用。

## 10. 参考图路由
多参考图必须明确职责，例如：
- 人物参考图：锁脸、发型、体型。
- 服装参考图：锁服装结构、材质、配饰。
- 场景参考图：锁空间拓扑、材质、陈设、机位关系。
- 开场参考图：锁站位、人物关系、第一帧状态。

提示词必须明确“什么保持不变、这次只改变什么”，禁止只写“参考图保持一致”。

### 冲突优先级
1. 人物身份不可变层。
2. 场景不可变层。
3. APPROVED 正式资产。
4. 当前版本层。
5. 临时状态层。
6. 普通剧情参考图。

普通小冲突按层级自动裁决；涉及脸、体型、核心发型、空间拓扑、核心家具、关键服装结构的冲突必须询问用户。

## 12. 质量 Gate
### 核心资产
- 核心人物资产。
- 场景主资产。
- 开场参考图。

总分必须 ≥95/100。

### 普通资产
- 普通配角。
- 群演合板。
- 临时扩展图。

总分必须 ≥90/100。

### 三项硬 Gate
以下任意一项 <95，禁止交付：
- 剧本符合度。
- 人物一致性。
- 场景空间一致性。

提示词不合格时自动重写再评分。成图必须目视核对硬约束；评分、格式检查与用户采用分别记录，不能相互代替。成图返修按第 13 节及批量模块处理，不能只改分数或无限近义改写。`.md` 只保留最终评分，`.txt` 不展示评分过程。

## 13. 图像诊断
用户只说“这张不对”时：
先自动诊断，再给极短候选问题：人物不像 / 服装不对 / 场景结构不对 / 构图不对 / 光影不对 / 色彩不对 / 电影感不够 / 其他。

### 人物不像
1. 脸型 / 五官比例 / 骨相。
2. 发型 / 发际线。
3. 年龄感 / 肤色。
4. 身高 / 体型 / 肩宽。
5. 服装 / 临时状态。

### 场景结构不对
1. 空间拓扑。
2. 门窗 / 通道 / 楼梯。
3. 核心家具 / 固定陈设。
4. 空间比例与尺度。
5. 材质。
6. 构图与机位。
7. 光影与色调。

### 电影感不够
1. 构图与视觉重心。
2. 空间层次 / 前中后景。
3. 光影塑形。
4. 色彩与最终电影调性。
5. 材质真实度。
6. 焦段与透视。
7. 颗粒 / 锐度 / 高光等润色。

### 构图不对
1. 主体位置与视觉重心。
2. 人物/物体空间关系。
3. 前中后景。
4. 留白与边缘安全区。
5. 视线 / 运动方向。
6. 对称 / 三分法 / 引导线等。

### 服装不对
1. 类别与整体版型。
2. 上下装结构与层次。
3. 关键颜色与配色。
4. 面料材质。
5. 领口/袖口/腰部/裤型等结构。
6. 鞋子。
7. 配饰与临时状态。

### 光影不对
1. 主光方向。
2. 主体与空间塑形。
3. 明暗层次与黑位。
4. 冷暖关系。
5. 高光与反射。
6. 电影化补光自然度。
7. 最后调整整体亮度。

### 色彩不对
1. 是否偏离母视觉圣经。
2. 是否偏离阶段子视觉圣经。
3. 主体肤色 / 角色主色。
4. 阴影与高光冷暖。
5. 整体饱和度。
6. 色彩分离。
7. 局部色偏。

## 14. 版本与 CURRENT
- 小改：`v1.1 / v1.2`。
- 核心身份、场景拓扑、关键服装结构变化：`v2.0 / v3.0`。
- 所有历史版本保留。
- `CURRENT` 指向当前正式使用版本。
- 每次升级记录：来源版本 / 本次修改 / 保持不变核心 / 是否 CURRENT。

### 局部编辑优先
- 局部增删、颜色微调、轻微灯光、家具小改 → 优先编辑原 CURRENT。
- 大幅换机位、原图不可见空间、核心换装、空间结构变化 → 重新生成。
- 用户只要求改一处时，禁止顺带改变其他已确认内容。

## 15. APPROVED / ALTERNATES / REJECTED
正式采用有两种有效依据：用户确认，或用户明确委托后按已确认设定和质量规则自主确认。记录采用依据及对应用户指令；不得把受托确认写成用户逐张采用。
- 仅获“连续生成／全部生成”授权时，目视合格图仍为待选候选；继续其它无依赖项，不逐批停等。需要尚未采用的母版时，只阻塞其衍生项，并集中请求最小选择或委托。
- 已获“后续由你确认／监督审图入库”等明确委托时，在授权范围内自主复核入库，不重复询问；超出范围或存在实质且无法裁决的冲突时才请求最小裁决。
- `APPROVED/`：内部正式资产来源。
- `ALTERNATES/`：内部次选备用。
- `REJECTED/`：内部不合格资产，不进入正式资产库。

以上目录只用于内部筛选与版本管理，不作为用户可见交付结构。最终仅把确认后的图片复制到单一扁平交付文件夹，并应用 `角色-`、`场景-`、`道具-` 前缀；内部 `.md/.txt` 不随图交付。

## 16. APPROVED 成图反向固化

- 重新读取实际成图。
- 对比原始设定。
- 轻微视觉差异可写回视觉锚点。
- 若差异涉及脸、体型、核心服装、空间拓扑等核心设定，必须先询问用户。

保留双重基准：
- 原始设定：定义“应该是什么”。
- APPROVED 成图：定义“视觉上实际锁成什么”。

生成精简视觉锚点摘要用于后续续图。

## 17. 视觉锚点摘要
### 人物固定骨架
- 脸。
- 发型。
- 年龄感。
- 肤色。
- 身高/体型。
- 当前服装版本。
- 不可变特征。
- 特殊角色可追加角、翅膀、纹身、机械结构等。

### 场景固定骨架
- 空间拓扑。
- 门窗。
- 核心家具。
- 主材质。
- 关键位置关系。
- 当前状态版本。
- 当前机位版本。
- 特殊场景可追加法阵、悬崖、巨构、特殊光源等。

### 注入规则
- 不可变核心字段：每次强制带。
- 当前任务相关字段：动态补充。
- 无关字段：不重复塞入。
- 参考图很明确时可压缩文字锚点，但不能省核心身份/空间锁定。

## 18. 当前上下文
维护三个当前对象：
- 当前人物。
- 当前场景。
- 当前开场参考图。

短指令如“改夜晚 / 换衣服 / 反打 / 镜头后退 / 再来一张”自动作用于最明确的 CURRENT 对象；目标不唯一时才询问。

最近使用历史栈保留 3–5 个对象。

### “继续生成”
- 正在改单个资产 → 继续当前资产。
- 批量任务 → 从持久化队列恢复，按批量模块混排返修与独立新图；当前难项不独占整个队列。
- 当前资产已确认且无后续任务 → 下一个依赖就绪的资产。
- 存在两个以上合理目标才询问。

### “重新生成”
- 只说“重新生成/再来一张” → 同提示词、同锚点纯重抽。
- 说“人物不像/场景太挤”等 → 自动诊断并只修改相关提示词。
- 点名具体修改 → 只改该部分。
