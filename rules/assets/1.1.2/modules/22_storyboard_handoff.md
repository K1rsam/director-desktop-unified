# 分镜资产接续与已有队列对账

收到已采用分镜和完整资产接续资料，或用户要求根据分镜查漏/续生图时读取。本模块不要求3008服务，不改变普通洗后剧本三行清单模式，也不因维护、审计或登记漏项调用图片服务。

## 季范围接续：批次派发前硬门

上游启用 `productionScope` 时，先读取完整源材料、已锁定季范围、当前总库和由 `assets.mjs image-queue` 独占创建的 `series-image-queue-v1`。完整源只供核源、结尾与连续性理解；设计、提示词及图片任务均限制在已选季。不能从全剧三行、全总库或未来形态/服装重新扩出全量队列；缺本季源用途的资产交回上游核源，不猜名字、不静默过滤越界项。未锁定范围拒绝设计或生图。

图片清单只收显式实际用途：`uses:[{assetId,assetRevision,episode,sceneId,purpose}]`。清单的 `items` 固定稳定ID、单项设计版本、`designHash`、完整采用设计、精确 `filename`、祖先设计版本和源用途；`assetRegistry` 绑定实际不可变快照，`productionScopeHash`、`queueHash` 固定范围与清单。纯声源不自动加图。祖先设计/旧图可以只读参考；没有列在 `items` 的祖先、其它状态和历史库项均不成为生成任务。

每次批次派发前，先落盘 `series-image-batch-v1`：顶层带 `queueHash`、`sourceHash`、`productionScopeHash`，`tasks` 只复制本批所需清单项的 `itemId/taskId/assetId/assetRevision/designHash/filename/uses`。一项一个候选任务；返修保留原任务ID并另记尝试依据。不得手造ID、重命名、将新版本号贴给旧图或只改hash掩盖设计变化。

实际执行本Skill自带的只读校验器（路径均为本机实际相对/绝对路径，可跨电脑重定位）：

```sh
node scripts/validate-season-image-queue.mjs --queue 本季图片清单.json --batch 本批候选任务.json --registry 当前总库目录 --source 原始源文件
```

`--source` 指 `sourceHash` 对应的原件副本，不以提取正文冒充原件hash。校验器核源字节、清单与范围hash、库身份/快照、当前实际消费项与祖先的设计版本、任务ID、文件名及本季用途。保留旧快照目录；无关总库新增不使本批失效。每批实际执行并保存简短回执，非零退出则不派发本批，也不改为普通三行模式绕过。源、设计或用途变更须回上游按版本更新并重新建立清单。该命令不调用图像服务；校验通过也不授予生图或采用权限。

本Skill内 `scripts/season-scope.mjs` 是独立总导演Skill同名纯标准库模块的逐字节副本；范围规则只有这一实现，维护时同步副本并运行同源检查。未启用季模式的旧工程保留原流程，不强制迁移旧队列。季清单的 `approval:design-and-uses-approved` 仅表示设计和用途可供任务使用，`imageState:not-generated` 不代表图片；后续候选、目视复核和用户/受托正式采用仍分开记录。

## 读取与身份

1. 读取交接清单，核源、方向、当前总库ID/版本、最终采用分镜及配套图片目录是否同一有效交付。按包内相对路径及旧路径映射定位，不能依赖原电脑路径。没有某份资料就报告具体缺口，不能自称全库对账完成。
2. 最终当前总库决定身份、状态、完整采用设计；采用分镜决定实际用途和第一帧；图片目录决定本次导入范围和精确文件名。总库可能大于本次图片范围，不把纯声源、仅提及项或全部历史状态都加入生图。
3. 沿用`assetId → 内部name/key → importName → @令牌 → 图片filename`。有明确安全名/文件名时优先沿用，不用三行原名重新命名；内部中文称呼、别名和家族另保留。无该映射的普通剧本仍按主入口三行规则命名。
4. 继承已确认的视觉方向、当前完整采用设计和已有正式图；不再重开三套视觉方案。人物七视图、场景拓扑及正式采用规则仍按本Skill执行。真实图片与白图占位分开，不把有PNG文件当作正式图已经生成。

## 分镜补漏

用户要求查漏时，从实际画面、入口/末态和单元道具反查总库，再查图片范围与已有队列。尤其核持握、交接、特写辨认及后续接戏依赖，不只查有没有@。

逐项判定已有资产/别名复用、新的正式道具、由指定场景设计覆盖的固定细节，或文字/特效表现。记录源/设计依据、实际集场单元与用途；不用正文出现的每个名词建图。源必需漏项和有据导演新增分开，不能把推定外观伪称原文明示。

没有登记的正式候选先交回当前分镜总库的补项闭环，保存坐标和待补状态；由维护该库的执行者核重、补完整设计、登记ID/版本，并更新采用稿、实际绑定及新版图片目录后，再进入本次正式队列。若用户同时授权本会话维护该库，可按其原接口完成，不直接改不可变快照。不得自行发明全局ID、仅手加队列或改三行掩盖上游漏项。

## 已有队列增量

先读取已有队列、候选/正式图及采用依据；对账以稳定ID、单项设计版本、文件名和实际依赖为准，不能仅按中文名或整库revision判断。

- 新增图片项：合入原队列并保留首次使用与使用范围，不重复建另一队列。
- 同项设计修订：保留原图，将真实受影响项及衍生依赖标为待复核；实际兼容则记录兼容依据后复用，不能只把新版本号贴给旧图。
- 无关总库新增：不使已有项及其正式图失效。
- 本次不再引用：从本次待生成范围移出，保留历史项和图片，不删除、不自动重命名覆盖。
- 只有中文名、无法可靠判同物：留具体待核项，回查身份与用途，不猜合并。

更新内部队列及来源版本，分别报告新增、待复核、复用、待补与本次移出；待补不得计为已齐。图片生产、候选复核与正式采用继续遵循已有授权，不因本次对账自动购买新图或改写用户采用。只为受影响项更新提示词/图像，不重生整库。内部映射和增量资料不进入最终扁平图片文件夹。
