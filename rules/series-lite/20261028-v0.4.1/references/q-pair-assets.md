# 正常形象与 3D Q 版同图资产

用于采用分镜会出现人物 3D Q 形态的项目。资产设计及交接时读本页；作者、整编和独审所需的引用规则已进入岗位数据合同。只完成资产文字、父依赖及引用，不在本 Skill 自动生图。已有工程与旧稿不自动迁移。

## 两张图，按实际造型建立父子链

每个实际需要 Q 版的造型保留两项：正常形象图，以及同图包含该正常形象与对应 3D Q 版的对照资产。后者是一张图、一个稳定资产 ID、一个文件名；图中是同一人物同一衣装的两种表现，不是两个现实人物，也不是默认双人同框分镜。

| 示例资产 | 直接父资产 | 文字设计职责 |
| --- | --- | --- |
| 主角X默认形象 | 无；有既有身份母版则按实际继承 | 完整身份、脸发、体态、默认衣装与识别特征 |
| 主角X默认形象带Q版 | 主角X默认形象 | 同图正常形象＋该默认形象的 3D Q 版；仅有默认造型 Q 用途才建立 |
| 主角X婚礼形象 | 主角X默认形象 | 继承同一身份，完成已采用婚礼衣装及必要造型差异 |
| 主角X婚礼形象带Q版 | 主角X婚礼形象 | 同图婚礼正常形象＋对应婚礼 3D Q 版，不直接套默认装 Q 版 |

同身份的不同造型不交叉借用 Q 对照图。已确定的 Q 用途在初始资产设计一并覆盖；创作中新采用的 Q 用途按本集记录、按批次补入。不预建所有衣装与 Q 版的笛卡尔组合，不按普通表情、动作或姿势拆图。源明确或已采用的 Q 形态不能为了省资产被删掉；普通夸张表演、速度线、非人物图解不因此强制立图。

所有条目沿用一个身份家族，`originalName`可同名，正式`name/key/importName`区分具体资产。总库实际分配ID后保存`parentId`；`design.dependencies`另记真正继承的直接父项ID、设计版本及用途。婚礼带Q版依赖婚礼形象，婚礼形象再依赖默认形象；不因拥有同一根身份就把所有父项写成默认形象，也不把“带Q版”写成两项相互依赖。

图片生成所用的直接父图是**当前正式采用的对应造型图**。文字设计依赖版本不能代替父图版本或内容hash；已知时在现有附件/交接说明记录父图文件、采用版本或hash，未知明确写“等待父图”，由生图侧接收时解析，不虚称已看图。需先生成的父项显式入队，已有相容正式图复用。直接父图变化只检查实际继承它的派生项；若变化影响身份、衣装或材质，更新该对照图，不能留下旧Q版却标成已同步。设计变更仍走原有局部修订，无关用途追加不触动设计版本。

现有图片队列的`item.dependencies`包含展开的祖先链，不能把每个祖先都当直接父图。直接设计继承看`item.design.dependencies`，身份父子看总库`parentId`；本例婚礼带Q版的直接父项是婚礼形象，默认形象只是上一级祖先。接收侧据当前采用记录解析真实父图，不凭名称或数组末项猜测。

## 资产库文字写法

以下为填写骨架，示例名不能当成真实设计直接采用。内容进入现有`design.full.body`、`design.dependencies`与用户可读资产MD；不另建权威表，也不把内部说明塞进视频提示词。

- **正式名称**：主角X婚礼形象带Q版
- **身份与源依据**：与主角X同一身份；填写实际集场、源明示或已采用幻想依据。
- **直接父资产**：主角X婚礼形象；填写真实ID、设计版本及继承内容。
- **父图依据**：对应婚礼形象的当前正式图；未提供时标等待，不以默认形象图替代。
- **图像组成**：一张正常形象＋3D Q版对照图。正常部分保留父图的当前造型；Q版部分沿用相同身份辨识、脸发特征、婚礼衣装结构、主配色及标志性细节，具体特征依已采用父设计填写。两部分完整、清楚、彼此可区分；不是剧情双人站位图，不要求视频保持参考板布局。
- **Q版造型**：根据项目视觉基准写明头身比例、轮廓及立体材质的设计选择；保留本人辨识，不能只是把正常模型等比缩小，也不能因Q版字样变成二维贴纸。表情和动态变形留给分镜，不冻结为唯一姿势。
- **使用范围**：本人物本婚礼造型出现Q版的片段，含正常转Q、Q转正常和纯Q表现；无Q片段使用主角X婚礼形象。
- **交接状态**：完整文字已采用／等待父图／已有正式父图可接续，据实填写；文字采用不等于图片完成。

正常形象卡保留完整外观设计。带Q版卡明确继承哪些已采用设计、允许改变哪些比例，并携对应完整父设计；不重新发明第二套人物衣装。参考板精确布局、尺寸、排版及生图实现由接收侧按此文字合同处理，本次不另设生图模型或审图流程。

## 分镜选择与服装分工

- 同一造型无Q的独立视频片段只引用正常图；含Q的片段只引用对应“带Q版”图即可覆盖正常和Q形态，不为父依赖重复引用正常图。其它人物各按自己的实际用途选择。
- 主观Q形态以`visualSubjects`描述，用`visualSubjectBindings.assetKey`指向该对照资产，并纳入`bindings/imageBindings`。正常现实人物与声源身份仍按实际保留在逻辑绑定；父设计无需为了供料自动变成图片引用。源定真实变身使用实际现实状态，不伪记主观幻想来通过检查。
- 正文写清哪些镜头用正常形态、哪些用Q形态、进入与退出及作用对象；同图两种形态不自动表示同时出场，也不要求真人旁边常驻小Q人；可让Q本人独占画幅、贴脸近景或进入完整3D幻想空间。源或已采用设计确需同框化身时说明各自作用，不能平白多出另一个人物。
- 视频生成字段不重复人物服装、鞋帽和穿戴配饰的颜色、款式、材质、花纹或装饰，也不从旧卡回填。具体外观由实际绑定的当前图承担。完整资产设计和生图文字仍保留这些信息；未读图不声称已经核实服装。
- 原台词、正式素材名、抓袖口／脱外套／破甲等源定动作及衣装辨认线索的叙事作用保留。新图若不满足源定线索或必要动作，只处理该具体冲突，不改剧情，不用关键词批量删词。

只检查本次真实新增、变化及实际引用，沿用作者→整编→非作者独审；不新增逐集全库查重、专用审核岗位或逐镜审批。对照资产固定外观依据，不降低夸张表演、快速运镜与已采用幻想的力度。
