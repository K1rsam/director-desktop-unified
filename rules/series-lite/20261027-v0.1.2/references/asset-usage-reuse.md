# 已有设计的用途复用

供料、登记新集场用途或接续在制工程时读取；普通作者不需额外加载登记协议。

## 直接供料，保留内容核查

已知稳定ID、别名及状态直接按本集映射选取完整采用设计和真实父依赖。核心资产就绪即并行开稿，其余正式资产首次使用前完成完整设计。作者开工读完整源与必要设计，核本集具体矛盾；整集整编和非作者独审继续核实际画面、持物、操作与源要求。

不默认每集另派供料审核、兼容证明或逐集查重报告。只有未知身份/状态、实质源冲突或复杂操作的结构/适用性不明时，才针对具体问题处理；已核映射与未变设计直接复用。普通复用不为填报告重新查全库。

## 仅登记用途：record-uses

现有设计未变，只补集场用途，使用：

```sh
node scripts/assets.mjs record-uses --registry /absolute/JOB/shared/assets --input /absolute/JOB/asset-uses_v1.json
```

```json
{
  "version":"series-asset-uses-v1",
  "baseRevision":3,
  "requestId":"EP02-A0001-USES-01",
  "reason":"原文 E02:R4 仍使用已采用的同一门厅",
  "entries":[{
    "assetId":"A0001",
    "assetRevision":1,
    "uses":[{"episode":2,"sceneId":"2-1","purpose":"同一门厅内交谈","sourceRefs":["E02:R4"]}]
  }]
}
```

一次将已核的本集/小批新增用途放入entries批量写入一个快照；已知且无需补登时直接零写复用，不逐项制造快照。协议只接受上述批量形状。示例替换为当前库、已核身份和真实源坐标。reason简明写已有源依据，不另造核重报告。命令只追加 `registry.usageAnnotations` 并生成新版总库快照，不改资产任何字段、单项版本、`design.full` 或 `design.dependencies`。它不是新设计采用或单元消费回执。

供料筛选及图片队列用 `scripts/asset-uses.mjs` 的 `assetScopeUses(registry, asset)` 合并原 `scopeUses` 与**当前设计版本**的用途追加；旧设计版本的追加保留历史但不自动迁到新版。明确用途仍须符合locked范围和源要求，不能把任意源坐标当作适用证明。

外形、结构、操作边界或适用限制实际改变，仍走原 `apply/revise`，沿真实依赖复核；新资产走add。不能借record-uses绕过源冲突或把过期设计重新标有效。已发现的生产补项及单元消费仍走原apply/reuse、amend、sync闭环，不用新用途替代消费。

## 现有工程下一步接入

新工程使用本包工具直接登记。完整版和蒸馏版在制工程均保留原入口、冻结创作脚本及采用材料，不全量升级运行时；主控可从新版Skill绝对路径调用record-uses，对同一当前总库旁路登记用途，再据当前有效设计选择本集供料。旧供料工具未读取usageAnnotations时，由主控按新合并规则选材，不能假称旧脚本已支持新筛选。

先让当前恢复/采用流程按旧合法入口收口，再从下一次供料接入；不改旧完成证据，不将采用校验改成只核历史快照，也不放宽当前设计、依赖、源锁和消费规则。旧脚本若不能接受新快照，停止该局部接入并保存现状，不手改快照或替换校验器强行通过。此接入说明不是现有工程已实测声明。
