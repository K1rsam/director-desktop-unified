## 为什么不直接整体复制 OpenCLI image

核对 `clis/chatgpt/image.js`、`utils.js` 及其测试：

- 它会包装生成/改图提示词；不能不加记录地替换本项目冻结提示词。
- 等待逻辑已经排除 data URL 的半成品 canvas 快照；上游 [#1898](https://github.com/jackwener/OpenCLI/issues/1898) 曾报告“命令成功但图片未完整生成”，不能仅看退出状态。
- `getChatGPTImageAssets` 优先取网页资源，但仍保留 canvas 重绘导出兜底。这样的字节不能自动标成网页原始文件。
- `image` 命令没有本项目的持久 unknown 提交与采用合同；超时后重新执行会开始新发送，不能让原队列按此建议盲重试。

因此可以验证其独立于 content 心跳的浏览器命令运输、后台容器、下载事件和租约；最终入库仍需核对原请求、会话/分支、原图字节与直接父图。测试应先跑原版，再按明确差异接适配，不将修补版说成上游原版通过。

## 安装后的真实试验（2026-10-16）

用户安装扩展 1.0.24 后，`doctor` 确认连接，网页 status 确认登录。本机以普通已登录 Edge 的自有工作页、`windowMode=background`、persistent session 串行运行。没有调用前台鼠标键盘、复制登录 cookies、切换生图渠道或提交视频。浏览器页面的 `hasFocus` 曾显示 true，不能将它直接作为操作系统窗口焦点证据；本次不声称所有窗口模式均已证明零干扰。

### 实际定位并修复的问题

1. **临时会话地址被反复导航。** 原版将 `local-chatgpt:` 临时地址当持久会话，等待器反复跳转，实际日志出现导航超时并回到首页。隔离适配保持原文档，不导航临时地址；结果完成后再读取真正会话链接。
2. **附件已上传却误报失败。** 新网页输入框只有 `contenteditable=true, role=textbox`，旧附件检测器没有这个选择器。真实页面有父图附件、发送按钮和成功上传回执，但检测仍失败。回归先复现失败，再补选择器。通过代码调用顺序、退出错误和空白草稿/零用户回合证明尚未发送，从原上传草稿做第一次发送，没有重新上传或另建相同请求。
3. **父图被误认为新输出。** 父图从草稿 data URL 变成消息 blob URL，原版误判为新生成图并提前退出。实际看图否决了这个候选；原文件与日志保留。严格模式只接受明确 `generated-image-gallery` 的结果，排除父图、历史附件及 canvas。随后取回同一原任务的真正围裙图，没有重复生成。

可复现补丁、源码哈希和五项专门回归位于 `scripts/research/opencli-chatgpt-20261016/`。补丁在原件副本成功重放；Windows 行尾处理使 utils 原始字节摘要不同，LF 归一后逐字相同，两个摘要分别保存。它仍是隔离适配，不是已发布桌面代码。

## 同一请求生成三张独立图片（2026-10-16 后续实测）

用户要求在一个网页会话、一次消息里给出三张图片的提示词，验证是否能全部下载。实际只发送一次：A 红色陶瓷狐狸、B 钴蓝机械热气球、C 黄色复古台灯，明确要求三张独立成品，禁止拼图。

**结果：3 张独立成品全部生成，3 份官方原图全部下载、解码、人工看图和 SHA-256 比对通过。** 每张 1672×941，大小分别约 1.77 MB、1.57 MB、1.88 MB。三份官方下载请求通过 `Promise.all` 并发获取，含文件身份查询、读取及回传约 2675 毫秒。它证明一次提示词可得到多张独立成品，不证明服务端内部工具或模型真正同时执行。

实际发现两处旧单图假设不适用于多图：

- 网页用轮播展示三个结果，DOM 只挂载当前选中的一张。根据 `img` 节点数量判断只能看到 1 张。原本的读取观察器在确切本地进程身份核验后被停止，仅更换读取器；网页原任务未取消，未重新发送提示词。测试采集器按网页实际“显示生成的图像 1/2/3”控件逐张读取，并用生成图区字节哈希匹配官方下载文件，不能拿缺少的 DOM 节点当成缺失成品。
- 当前生成中的按钮 aria-label 是“停止”，旧 `isGenerating` 没有识别该确切标签，出现假空闲。采集器增加了该标签的完成前检查，确认原任务结束才下载；原版适配器本身和正式客户端尚未接入这个后续修复，不能把本次测试采集器的能力算到当前发布版。

已同步补强独立只读恢复候选的活动任务拦截，识别确切“停止”/“Stop”按钮，并用当前中文按钮形状的 DOM fixture 验证不会导航离开生成中页面。本目录当前专项回归共 11 项通过；这不等于原版 `isGenerating` 或正式客户端已经完成同样修复。

三张返回的顺序为 **A 狐狸、C 台灯、B 热气球**，与提示词 A/B/C 不一致。测试人工审核后保存了独立映射，没有按输出序号直接绑定资产。将来接入桌面批量资产时必须验证资产对应，不能只依据顺序、通用“已生成图像 1”标签或提示词条目位置自动采用；含直接父图的任务还须保留原依赖边界。

原始 attempt、观察、采集器、官方下载证明及人工审核保存在忽略目录 `.local/research/web-images-20261016/rounds/three-in-one/` 和其同级测试脚本；可公开摘要及证据文件哈希见 `scripts/research/opencli-chatgpt-20261016/multi-image-acceptance.json`。不提交私人会话链接、网页登录材料或图片。该轮未提交视频，未替换 EXE，未修改生产项目，未把单轮成功升级为长期多批稳定或并发上限已验收。
