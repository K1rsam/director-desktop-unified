# 第四阶段：项目查找、文件计数与阅读布局修复

本轮基于 `28b3ffa`，分支 `feat/lingmo-stage4-import-20261023`。

## 问题与处理

1. 已导入项目存在于真实项目登记中，旧列表按登记顺序显示，新导入项目排在列表末尾。改为按创建时间从新到旧显示，增加项目名称搜索，返回项目列表时回到顶部。无原始剧本、已有导入分镜的项目重新打开时默认进入第四阶段；不要求重跑前三阶段。
2. 资产数与文件夹文件数没有清楚区分，关闭回填窗口后未匹配文件也缺少恢复入口。增加只读 `lingmo.media.latest`：读取持久化扫描回执和真实媒体关联，显示资产数、上次扫描文件数、已入库和未入库文件数；支持恢复未入库清单，继续显式选择目标版本。该读取不重新扫描、不创建资产、不采用图片、不触发生成。
3. 分镜目录缩为 150 px；长正文使用固定高度容器内滚动，完整文字与标签保留。参考图移到正文上方，改成 128×76 px 的紧凑卡片，保留原图查看、图片顺序与绑定控件。

## 当前项目实测事实

通过真实项目的只读登记、持久扫描回执、媒体关联，以及 SQLite 一致性隔离副本上的新版 Rust 核心接口核对：

| 统计对象 | 数量 |
| --- | ---: |
| 文档资产 | 591 |
| 上次文件夹扫描文件 | 619 |
| 已入库文件 | 591 |
| 未匹配、未入库文件 | 28 |

不是 621 项资产减少到 591 项。28 份文件未找到当前文档的精确资产身份或形象名称，原文件仍保留。没有为了补齐数字而模糊绑定、合并形象、删除文件或自动增加未引用资产。具体文件名与原路径仅存本机 `.local`，未提交。

已有真实项目、591 个媒体及采用关系、1323 个片段均保留。新版接口用隔离副本验证，未让一次性核心进程接管正在运行的真实客户端。
