# SDK 中断、耗时与成稿审核

## 已确认的中断原因

C 项目第三集的原始事件是官方运行器 `Reconnecting... 2/5 (stream disconnected before completion: tls handshake eof)`。旧桥把顶层 `error` 直接当终态并 abort，打断了仍在重连的原 SDK 流。网络 TLS 中断本身的根因尚未证明。

修复只接纳活动 turn 中格式明确且计数有界的重连诊断，等待同一原流的正式结束，不调用第二次 execute、不创建新 thread、不延长总时限。真正失败、缺失终态、非法事件和超时仍保留为未知提交。集成后的 SDK bridge `npm run verify` 70 项通过；没有真实模型调用。后续输入格式兼容测试独立记录，不能用这些离线结果证明旧请求完成。

## 旧第三集不能安全重发

原第三集没有最终结果、用量或进程终止收据，只有五个原始事件；运行器使用 ephemeral 模式，未找到对应的持久会话。当前接口仅核对本地回执，没有远端被动对账功能。`resumeThread.run` 会产生新 turn，不能冒充恢复原请求。

C 的提交未知状态、原范围和请求继续保留。不能通过切换 CLI、复制项目、修改数据库状态或缩小集数范围解除它。新重连补丁无法追溯创造丢失结果。升级桥接代码也不能覆盖旧请求的运行身份；旧回包读取与新任务执行必须分开验证。

B 项目是独立的原 CLI 流程，没有未解决的已派发文本节点。已保存第一集六个单元；第二集有原回包但尚未正式发布。已有恢复补丁在稳定副本回放了十四个封存节点，恢复两集共十三单元，并停在未派发的第三集规划。客户端应使用原流程“继续原流程”入口，不另起缩范围任务；实际恢复与第三至十集仍未验收。

## 本轮 SDK 兼容修复

新桥接程序只读声明支持的输入格式，新节点据此冻结 `text-attempt/v3` 和 `rules-first-json/v1`，将完整规则前置。旧 bridge 没有该声明时仍使用 v2。既有请求、原 v2 编译器、语义哈希、原文字节和 schema 不变；新格式进入 attempt 封套哈希，执行、回执核对与重开都按冻结格式选择。全部输入校验完成后才分配持久节点，不能因格式错误先占住节点。

另将历史身份读取与执行权限分开：已接收或已完成的原包仍走既有 `sdk_raw` 校验；历史未决任务只核验原始 JSON 封印、请求、线程和日志关联，始终保留 unknown，不启动 Node、CLI 或旧运行器，不覆盖回执、不采用迟到且未经领域校验的结果。真正执行继续核对当前 bridge 摘要，不能借历史兼容派发旧身份。此修复仅解决升级后的读回，不授予跨 bridge 继续新节点的权限，也不能恢复缺失的第三集回包。

## 已完成稿件的实际审核

| --- | ---: | ---: | ---: | ---: | ---: |
| C 第一集 | 8 | 47 | 37 | 6 | 0 |
| C 第二集 | 6 | 43 | 35 | 3 | 0 |

C 第一集另有四个短于两秒的镜头，第二集五个；最长分别 7.5 秒和 6.5 秒，B 最长 7 秒。较长镜头承载完整对白或连续动作，没有十至二十秒的静态镜头；不能为比例机械切碎台词。原文区间完整、不重叠且顺序一致；已绑定资产和形象 ID 均存在、名称一致。这些是文本检查，不代表图片、发声或视频成品验收。

语义审核还发现以下缺口，保留原稿，没有人工填补后冒充流程通过：

- 群像中的同一说话成员跨单元出现性别代词变化，现有 assetId 检查不能覆盖群像内部身份。
- 两人联合说者标签含 `&` 时未被旧解析器识别，原话保留在声音文本，但没有进入结构化对白覆盖和时窗检查；不能把“已识别对白 100%”当作所有对白都验收。
- C 将需要独立近景的交易角色归入群像，并漏掉实际交互道具。B 已有更细粒度的角色与道具，合并时必须保留。
- B 一个单元使用了已登记的手机，却没有带上对应素材引用，连续性取料还需补检。

多人共同台词已做隔离 parser 候选与反例验证，但没有直接合入。原因是下游仍只有单一 `speaker`：第一阶段检索把联合标签视作一个名字，资产和主创输入没有成员合同。仅放宽正则会把问题继续传给模型。完整修复需增加仅对新解析版本生效的成员字段、按成员检索证据、保留传输回环验证，以及“共同发声覆盖一次”的主创约束；旧版本和冻结原文必须保留。私有候选和实施清单位于 `.local/validation/multi-speaker-patch`，不能把该候选测试通过写成全流程已修复。

第四阶段代码直接由同一非 retired 单元集合计算全集和分集。稳定快照 C 为 8+6=14，B 为6；没有独立旧全集存稿。新集发布后的界面切换和保存重开仍需实际验收，不能用数据库相等替代。

## 耗时证据与优化边界

C 第二集八次已完成 SDK 调用合计输入 788,986 tokens、输出 69,825 tokens，创建至采用累计 1,755.919 秒（包含本地校验），回包缓存计数均为零。最慢两次主创分别约447秒/16,211输出tokens和394秒/14,385输出tokens；输入最多的整编为120,207tokens，却在约26秒内输出481tokens。因此主要耗时包含实质创作和有界修订，不能把长输出一概认定为死循环。

现有源行共享、资产卡投影、连续态等值引用和可重建导出剥离已生效，不再叠加通用摘要层。本轮仅对后续新 SDK 请求实施与 CLI 一致的完整规则前置序列化；内容逐值不变，旧冻结编译字节不变。内存比较同岗位规划的共同前缀从65提升到31,399个UTF-16单位，但方法卡不同的请求仍只共享约1,600–1,900；不能承诺实际缓存命中或固定提速比例。
