# 软件级渠道设置与连接修复

## 问题与边界

原设置页挂在 `Workspace` 下，Rust 分发也先打开 `projectId` 对应的项目，所以未选择项目时无法配置本机 SDK、CLI 和渠道。另一个组合错误是：保存设置让 App 暂时进入 busy，子组件把 `writable=false` 误当成权限撤销，导致“自动连接”在保存成功后提前结束。组件独立检查通过没有覆盖这一父子生命周期。

本轮将账户、可执行程序、文本渠道、模型和推理强度放在软件级设置；无需项目、无论第三阶段有无成稿，都允许显式连接检查。制作风格、画幅、图片和视频的生产参数、素材、备份与已有成稿继续属于项目。功能包已接入与账户连接成功是两种独立状态，渠道页不再显示第三阶段功能横幅。

## 持久化与执行约束

- 全局设置使用独立合同 `app-settings/v1`，不创建隐藏或虚构项目。
- 全局检查请求使用 `scope: global`，不依赖或携带当前 `projectId`。
- 保存配置与只读检查分开；明确点击连接后必须继续实际核验，临时忙碌不代表撤销权限。
- 全局配置只作用于新请求。项目设置原值、历史请求、原回包、未知提交与恢复预算保持原绑定。
- 全局账户或模型检查不恢复、不提交任何项目任务。
- 旧配置迁移记录来源；不凭项目更新时间随意选择存在冲突的账户配置，不清除已有凭据。
- 连接结果可在同次软件运行中保留最近检查时间；再次点击检查仍执行真实只读核验，不能根据缓存或既有成稿跳过。

## 验收记录

### 按 SHUO 设置闭环整理

对照本机 SHUO Canvas 0.8.1 的组件设置、账户设置和各自 API 实现，采用其“组件状态、安装、账户授权、检查结果”分离的交互顺序，用现有 Rust/React 重新实现。没有复制其混淆代码进入本仓库。

- OpenAI 单卡管理 Codex CLI/SDK；先只读检查本机组件，缺失才由用户点击安装。已有程序复用，组件状态不冒充账户登录成功。
- 即梦只显示生成 CLI 账户卡；Canvas 未完成的运行桥不继续占据主要账户设置区域。
- BH API 和 Chrome 网页各自独立，配置与检测放在同一张卡片，路径及手工参数折叠。
- 连接操作有各自的执行标识和取消保护。用户操作等待已有状态轮询完成；后台轮询忙时跳过，不能静默吞掉用户点击。
- 全局新模型/执行方式立即投影到阶段页面，旧轮询不得把界面还原到旧值。全局和项目目录检查均走不会恢复任务的 global 路由。

### Chrome 原链路恢复

确认 Windows 上仍存在旧版 6.4.0 Bridge、2.4.5 扩展和旧 `bridge.env`。新增自动发现、明确选择配置文件导入、本机连接、只读检查和打开 Chrome；凭据不回传界面。原执行器的单次提交、原关联码恢复、原生图片来源与文件哈希验证继续保留。

新启动只使用应用自己的数据目录，不接管旧工作流数据库；拒绝指向外部目录的 reparse/junction，启动失败清理本次子进程。浏览器打开入口查找真正已装扩展的 Chrome profile，避免使用旧测试目录中的空 profile。端口被其他服务占用时不覆盖；没有扩展网页、多个未选定网页、忙碌和真正可执行分别显示。旧检查缓存携带时间和连接身份，不能在换凭据后继续显示已连接。

独立复核发现 Bridge 自身会恢复 `workflows/state.json`。因此启动前增加有界只读检查：只有文件不存在或版本 4 的空工作流表可启动，非空、损坏、超限及外链均保留原数据并拒绝启动，不通过清空记录绕过。最终该模块 8 项 Windows 回归通过，包含活动及已停止工作流、损坏状态与目录 junction；没有发起生成。

尚未把第三方 Chrome Bridge 打包成新的自动下载安装器；本轮恢复已安装组件，并提供已有连接导入。全新机器缺少 Bridge 或 Chrome 扩展时会明确提示，不能将“未安装”显示为可用。
