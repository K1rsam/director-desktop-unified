日期：2026-10-14。基于 `integration/windows-mac-20261008` 的 `c1fac32e8e8c5e0801f34942759cbbfb4cc4d169`，保留原 Windows 工作区改动，逐项集成。本文区分工程回归、真实本机状态与尚未验收的生成链路。

## 专属浏览器

- 新增全局专属 Edge 入口：官方登录、后台启动、检查与恢复、只读状态；不要求选择项目。新图片绑定显式保存，历史任务保持原浏览器身份。
- 专属持久 profile 与用户日常 Chrome/Edge 分离；不复制 cookies。仅首次官方登录打开可见窗口，正常执行采用隐藏、无焦点页面。
- 外部管理组件核对 PID、进程创建时间、完整启动身份及 loopback CDP listener 归属，不能按进程名称结束浏览器。
- 已核实 Edge 重开时会禁用命令行加载的 unpacked 扩展；管理组件通过专属实例的设置 API 与 CDP 加载经过核验的组件，不改系统策略、用户正常 profile 或 Preferences 文件。
- 生命周期操作检查全部登记项目（含已归档项目）、桥接队列、扩展状态和原任务；未决提交、正在执行或归属不明时保留原实例，不借恢复重发。
- 网站首页附带正常查询参数仍属原控制页；会话路径和外站不能成为后台控制页。网站校验、登录状态、扩展连接和可生成状态分别显示，不绕过网站校验。
- 升级后即使新版管理组件尚未落盘，只读状态仍使用程序内置模块检查原实例；不会把正在运行的旧实例误报为未启动。模块和非公开连接参数通过 stdin 传输，不进入进程参数。
- UI 的公共图片渠道名称改为“ChatGPT 网页”，兼容现有 `chrome` provider 身份与历史请求。

## 实际发现的 SDK 问题

新案例第一阶段在创建官方 SDK runtime 之前失败：Rust 传入 Windows 正斜杠路径，而 Node 的 `path.dirname` 返回反斜杠路径；旧代码直接比较字符串，报 `SDK_NATIVE_IDENTITY: attempt directory`。不是网络等待或已证明的模型失败。

路径修复使用规范化绝对路径，并继续拒绝父目录跳转、外链和不匹配的 attempt 身份。原失败任务及回执保留；恢复必须使用原 workflow/job/attempt 的窄证据协议，不能删除旧意图或另建任务绕过 unknown。

第一次真实恢复暴露了第二道原生监督器校验未采用恢复身份的问题：`SDK_WRAPPER_FROZEN_ATTEMPT_MISMATCH`，SDK 子进程随之报 `write EOF`。修复通过独立 `wrapperPreparationRepair` 预约、固定失败版本和进程停止证明限定恢复范围，原意图、回执及运行目录保留。它不放宽普通网络中断或已有 SDK 事件的未知提交。

本地 02:43:54 从同一原 workflow/job/attempt 开始受保护恢复，02:51:32 完成第一阶段：F2 资产目录完成后自动进入 Q1 资料整编，共发布 47 个资产和 10 集制作基础。两条派生关系保留直接父资产。F2 使用 45,408 input / 9,361 output tokens；Q1 使用 55,459 input / 2,580 output tokens。接收、领域验收、采用和后继推进均来自真实 SDK 执行，未以新工作流绕过原记录。

还发现恢复中的界面进度缺口：任务在可信终态落盘前保持 `submission_unknown`，旧投影因此不展示新的 SDK 事件。补丁仅在工作流和节点运行中、数据库恢复预约与准备记录匹配时，显示本次预约后的安全事件元数据；尚无新事件仍显示未知，原状态、原请求及私有正文保持不变。恢复用时从本次预约开始计算，避免把先前停留时间显示为本次执行耗时。

## 第二阶段新请求的取料与美术补足

新增显式 `asset-design-evidence/v1`。新工作流冻结合同正文与 SHA；恢复只沿用原合同，无版本历史请求不会自动升级。LOC 按准确集场 ID 提供锁定场次原文，即使已有部分视觉事实也不漏掉必要环境物件；GLOBAL 只按原引用定位场次，不扩展全剧。人物/道具继续使用原窄范围取料。场景事件造成的破坏与基础空间分开，阅读材料不自动升级为 SOURCE 事实。

制作资料的“原文未知”与“禁止美术设计”分开。原文未限定的完整日常衣装、包型和材质允许保守的非剧情美术补足，单列 `freeDesignScope`；明示约束、原文、当前有效状态、手写稿与直接父链均保留。设计收据绑定实际有序原文摘要和合同版本，旧回包不冒充已读新材料。无关坏父引用和单资产错误范围仅阻塞对应分支，正常资产继续。
