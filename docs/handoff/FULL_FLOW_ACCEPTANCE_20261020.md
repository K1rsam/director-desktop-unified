## 本轮已修复

1. 任务摘要与归档投影新增排队原因后，额外字段的数字索引发生错位。两个消费者都改按明确列名读取；归档不改任务、媒体与队列事实。
2. Windows 原子 JSON 写入针对短暂共享锁有界重试；使用原子替换并保留旧文件。Win32 调用改用规范的 verbatim 路径，支持超长项目目录与带 UUID 的临时文件。永久失败不删除原件，也不重跑业务。
3. 第二阶段新任务冻结 `asset-design-evidence/v2`。在准确适用集场内有界补入人物名称、动作及紧邻代词的原文窗口，最多额外 48 行 / 8000 UTF-16。只补 `SOURCE_CONTEXT`，不由程序制造性别事实；旧 v1 与历史冻结不升级。
4. 文件导入仅在首行严格等于真实文件 stem，且后续已解析为第一集或明确零集资料时，记录单行标题分类及来源证据。保留原文、哈希、范围、集场身份和 parser 版本；粘贴文本不借用调用方 path。
5. BH 图片按 SHUO 已核对的六个明确执行模板适配。`image2-high` 补固定 `quality_level=high`；`gpt-image-2` 使用质量枚举。UI 同步显示图片质量，旧尺寸不会被静默映射。
6. BH 上传携带 model；无凭据、有界读回官方签名 OSS 素材，核对字节数、SHA 与签名余量，并保存本地读回证明。旧未提交且缺证明的记录需重新准备；已提交/未知任务仍恢复原任务。查询兼容 `success`，首尾帧在上传前拒绝混入其他媒体。
