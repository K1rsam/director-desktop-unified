# 剧本格式兼容与后台判读

本轮以 `b464d28` 为基线，在 `fix/source-format-intake-20261027` 修复新剧本人物资料前言与 `1-0` 场号误判。没有改变四阶段路由、创作规则、图片渠道或视频权限。

## 用户行为

- 新导入先做本地识别。明确的人物小传、档案及不同零号场格式无需模型。
- 第一阶段存在可处理的集场疑点时，主按钮为“识别格式并整理”：先完成持久化格式判读，再以新源版本冻结制作基础任务。
- “AI识别格式”只处理结构，不开始创作；“重新识别”仍为完全本地操作。
- AI仅处理未确定的完整原行，提供附近上下文；不返回改写全文。不能确定的内容保留待确认，不伪称完成。

## 保真及恢复

新识别合同 `source-parser/v11` 仅在解析结果变化时启用；旧 v1–v10 继续按原合同回放。人物前言需独立标题与邻近资料锚点，零号场仍须正确集号与场景元数据。人工裁决之后仅剩空白的旧自动场不再形成幽灵场。

格式判读 `source-analysis-runner/v1` 冻结原文版本、哈希、规则、渠道及选择范围。模型请求交由现有 SavedTextExecutor，先验证再 accepted；原回包和 UNKNOWN 保留，不新建任务绕过未知提交。新源与回执原子发布，后继制作任务原子预约，重开后复用同一任务。

原文字节、SHA-256、UTF-16 坐标、行 ID 与人工裁决保持不变；范围外已识别内容不能被 AI 改归属。更新源只失效未提交任务，不删除历史媒体或改写冻结请求。

长剧本校验原先逐行从整份原文起点计算 UTF-16 切片，形成重复扫描；现改为连续边界、逐行 UTF-16 长度及最终完整字节重建等式，台词在其原行内检查。相同完整样本、相同依赖、相同优化编译设置的独立解析验证从 27.882 秒降到 7.895 秒，结果报告逐字节相同。这是本地解析基准，不是模型创作或所有机器上的速度承诺。

## 验证范围

本轮实际命令、结果、产物哈希和安装状态见同目录 `SOURCE_FORMAT_INTAKE_RECEIPT_20261027.json`。私有剧本与运行原回包只保存在 `.local/source-intake-20261027`，不进入 Git。

完整用户样本只读验收：4668 行、150 集、250 场；27 行前言识别为资料，阻断从 1 降为 0；无仅空白场。原文与人工决定保持不变，未写用户项目数据库。

模型兜底覆盖合成回包、越界、遗漏、重写、错误资料归类、UNKNOWN、accepted 后发布、CAS 过期、保存重开及后继单次预约。该样本本地即可解决，本轮没有调用真实模型来伪造验收，也没有进行剧本创作、图片或视频生成。

扩大原文相关回归时发现一个旧测试仍缺少上轮引入的已采用视觉基准。仅补齐该测试的合成前置条件，未放松产品门禁，并单独复测。

## 使用

安装后打开原项目即可点击“识别格式并整理”；只检查格式时可点“重新识别”或“AI识别格式”。无需删除、重新导入原项目。真正存在同号集冲突或非结构性歧义时仍显示具体问题，不以分类操作吞掉正文。
