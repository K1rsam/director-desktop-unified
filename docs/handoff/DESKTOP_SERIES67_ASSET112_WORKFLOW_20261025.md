## 5. 第三阶段：提示词与图片资产

### 5.1 支持三种来源

**本软件第二阶段成果：** 直接读取同版结构化稿/总库/图片目录，MD作为可读交换产物；不要导出后再反解析自己的 MD 才找回身份。

**外部分镜 MD + 完整接续资料：** 采用资产 Skill 模块22，核版本、方向、稳定 ID、用途与文件名后接续，不重开风格选择，不重新编号。

**只有外部 MD：** 沿用现有无损 parser，以三行清单/@确定正式图片范围与名字，回读相应分镜补必要设计，记录依据是 imported-md 而非原始剧本。没有完整设计/父子关系的范围如实留待核；能从已给正文可靠确定的内容自主补足，实质歧义只阻塞相关项。不得要求用户先回第一阶段重建整个剧本，也不得假称完整资产交接已校验。季模式资料不完整时不能退回全剧清单绕过范围限制。

导入完成后提供“编写/补齐资产提示词”和“打开配图/视频”两个入口，保留现有直接进入第四阶段的能力；重开项目记住合理工作页，不能每次把第三阶段工作中的 MD 项目送回第四阶段。MD 修订时用总库身份、externalId、版本与用途明确映射，不能因为文档 hash 变化就复制整套资产和已采用图片；缺稳定标识的来源保留待核，不按同名猜继承。

将当前只接受原剧本的 `image_design_source` 改为带来源类型的取料接口。不得把 MD 冒充原剧本，制造 sourceHash 或改旧源记录来绕过检查。

### 5.2 先写全量提示词，按依赖独立执行

第三阶段先为本次正式图片队列编写完整提示词正文及必要依赖说明。无图像账户也能完成、查看、编辑和导出这些文字。

对于父图尚未产生的子资产，可以先写齐目标设计、保持/改变项、参考图职责和版式。状态应显示“提示词已编写，等待某母版”，不能谎称已读取真实图像或已经具备最终可派发请求。

派发前，程序绑定真实 APPROVED 母图的路径/媒体ID、版本、hash和可核实视觉锚点，编译实际发送请求。仅补引用路径属于机械装配，不再给每个子项固定增加一次全文重写调用；实际锚点暴露矛盾时才局部调整。每次实际请求快照必须可回查。

常规按钮分开：**编写全部提示词、编写所选、复制/导出提示词、生成就绪图片、生成所选、导入图片、采用/切换版本**。已有范围和连续执行授权照常继承；编写提示词不自动启动图片收费任务。渠道未登录、母图等待或某张返修，都不能阻塞其它可做文字或独立图片。

### 5.3 父资产不等于必须补生父图

至少分开三类关系，沿用现有数据库 ID，不用名称相似猜：

| 关系 | 用途 | 是否等待图片 |
| --- | --- | --- |
| 同一身份/家族的父子状态 | 表示默认装、换装、年龄或形态等身份关系 | 不自动等待 |
| 完整文字设计依赖 | 子设计继承某母设计的具体版本 | 只依赖采用文字，无图仍可写词 |
| 实际参考媒体/合成依赖 | 锁脸换装、同景状态/机位、开场合成等依赖已采用图 | 派发或合成前须有对应有效母图 |

根母版和高影响依赖优先，其余按首次使用顺序稳定排列。父图失败只挡真实子项，独立项继续。存在循环、自身依赖、缺父项或错误身份时，给出具体资产链而非重跑全库。

**母图未在本次 MD 图片范围中：** 先查是否有可复用的正式母图；祖先设计可以只读参考，不能自动生成全部祖先。若某子项确实必须补母图，先显式登记“仅参考母版”任务、必要理由、所服务子项和本季实际用途，并计入新增图片数/费用及现有授权边界；不要伪造母项在分镜中入画。现有模块22不允许把未列入 items 的祖先直接派图，支持任务若需要扩展数据结构，定义有版本的桌面扩展合同并测试；不得伪装成原 v1 已支持或篡改 hash 绕过。仅参考图片保存在内部参考库，未被 MD 调用就不塞进最终 MD 图片文件夹。

### 5.4 提示词实际继承哪些方法

- 继承第二阶段确定的画风、身份、场景和用途，不让“电影风格”模板擅自把3D国漫改成真人，不重提三套风格。
- 成品提示词中文为主：任务类型 → 主体 → 不可变特征 → 服装/空间结构 → 参考职责 → 光影/材质/构图 → 简短避错。正文完整可复制，不把评分、流程和整个会话塞进去。
- 单人人物按 Skill 的 **1:1 七视图**、上排三脸、下排服装视图与指定白脸规则；群演按专用合板。非人主体按真实形态使用适配模板，不硬套人类版式。
- 换装锁脸必须保留 APPROVED 身份母版上排原像素：独立生成下排服装视图，再按固定槽位合成，逐像素验证；不能只在提示词写“保持同脸”就宣称完成。发型/年龄/形态实质变化先建立正确身份版本，不机械贴旧脸。
- 标准场景 **16:9、绝对无人、空间结构清晰**，保留门窗/通道/地标/表演区与尺度；昼夜、天气、机位只改变被允许层，不能重造空间。
- 角色板、场景、道具、系统视觉、开场合成使用各自版式和实际用途。视频画幅与资产板画幅分开存储，不能用项目16:9覆盖人物1:1。
- 多参考图各自限定脸/服装/空间/站位职责，明确保持与改变项。开场图只按实际第一帧状态，不提前放后进场人物；附加开场/多机位没有实际用途不自动批量扩项。
- 纯系统音、仅提及项、瞬时表演形变不自动建立图片任务；可见系统载体遵守已采用的呈现域和设计，不由资产岗改原声。
- 真实图像必须目视复核硬约束。保留 Skill 评分要求的内部记录时，不把分数当自动视觉检测或正式采用证据，也不为调高数字反复重抽无明确缺陷的图。

“GPT-image-2.5”是该 Skill 的目标名称，不证明桌面已能调用这一型号。实际工具/型号照真实渠道记录，无法核实则标未知；不改用户选定渠道，不为了方法迁移强接单一图片供应商。
